# terraform-postgresql-database

Creates a PostgreSQL database with an owner role (`<database>_migrator`), an application role (`<database>_app`) and
read-only / read-write roles (`<database>_ro`, `<database>_rw`).

## Schemas

`schemas` (default `["public"]`) lists the schemas the roles get access to: grants on existing tables and sequences and
default privileges for tables and sequences created later by the owner role. Every schema except `public` is created
and owned by the owner role.

```hcl
module "database" {
  source = "cookielab/database/postgresql"

  database = "app"
  schemas  = ["public", "app"]
}
```

## Write-only passwords

By default the owner and application passwords are generated by `random_password`, stored in state and returned in
`owner_user.password` / `app_user.password`. Setting `owner_password_wo_version` / `app_password_wo_version` switches the
role to the write-only `password_wo` argument (Terraform >= 1.11): the password is not stored in state and the
`password` output is null. Pass the password in `owner_password_wo` / `app_password_wo`, for example from an ephemeral
resource, and write the same value to its consumer in the same apply (e.g. `data_wo` of `kubernetes_secret_v1`).

A write-only value is written only when its version changes. The role's `app_password_wo_version` and the secret's
`data_wo_revision` are separate counters: they must change together, otherwise the role gets a new password while the
secret keeps the old one. Derive both from one value and change only that value to rotate the password:

```hcl
locals {
  app_password_version = 1 # bump to rotate the password of the role and the secret together
}

ephemeral "random_password" "app" {
  length  = 32
  special = false
}

module "database" {
  source = "cookielab/database/postgresql"

  database                = "app"
  app_password_wo         = ephemeral.random_password.app.result
  app_password_wo_version = tostring(local.app_password_version)
}

resource "kubernetes_secret_v1" "app" {
  metadata {
    name = "app-database"
  }
  data_wo = {
    username = module.database.app_user.username
    password = ephemeral.random_password.app.result
  }
  data_wo_revision = local.app_password_version
}
```

Switching an existing role to a write-only password sets a new password on the role and destroys its
`random_password`.

| Name | Version |

Basic usage of this module is as follows:

```hcl
module "example" {
  	 source  = "<module-path>"
  
	 # Required variables
  	 database  = 
  
	 # Optional variables
  	 app_password_wo  = null
  	 app_password_wo_version  = null
  	 app_username  = null
  	 create_role_ro  = true
  	 create_role_rw  = true
  	 encoding  = "UTF8"
  	 lc_collate  = "en_US.UTF-8"
  	 lc_ctype  = "en_US.UTF-8"
  	 owner_password_wo  = null
  	 owner_password_wo_version  = null
  	 owner_username  = null
  	 role_ro_name  = null
  	 role_rw_name  = null
  	 schemas  = [
  "public"
]
  	 template  = "template0"
}
```
